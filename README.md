# Hermes 科研雷达

本地的科研信息收集器：抓公众号与 B 站、归档原文、用模型精读、按相关度推给你。
跑在自己电脑上，数据也在自己电脑上。

## 启动与停止

双击 **Radar.exe**（开始菜单/桌面上的「Hermes 科研雷达」指向它）。它做三件事：拉起后台
服务、开一个界面、在右下角放一个托盘图标。

**开成什么样由设置决定** —— 设置 → 高级与诊断 → 「桌面程序」→ 双击图标时：

| 选择 | 效果 |
|---|---|
| 软件窗口（默认） | 自己的窗口（WebView2 内核，和 Edge 同源）：没有地址栏和标签栏，独立任务栏图标；点叉时能先问一句再决定关不关 |
| 浏览器标签页 | 打开你默认浏览器的一个标签页，关掉标签页不影响服务 |

托盘右键菜单里也能随时切（「打开方式」下面两项打勾的就是当前设置），改完立刻生效，
下次双击 exe 也按新的来。偏好存在 `data/shell.json` 的 `window_mode`，删掉这个文件就
回到默认的软件窗口。

### 点右上角的叉之后

默认会弹一个框问一句：**只关窗口**，还是**连后台服务一起退出**。框弹出来的时候界面还
在，等你点完才决定窗口收起来还是整个退出——不会出现「界面先没了、框才出来」。选「只
关窗口」服务继续在托盘里跑，双击托盘图标就重新打开。不想每次都问，到设置 →「桌面程序」
→ 关闭窗口时，把三个选项定下来：

| 选择 | 效果 |
|---|---|
| 每次问我（默认） | 关窗口时弹一次框，两个都行 |
| 只关窗口，服务留在托盘 | 不问，直接留托盘 |
| 连后台服务一起退出 | 不问，关窗口就等于彻底退出 |

托盘菜单里的「关窗口时」也有同样三项，带勾的就是当前设置。

### 开机自启

设置 →「桌面程序」→ 开机自启。它写的是当前用户的注册表 Run 项
（`HKCU\Software\Microsoft\Windows\CurrentVersion\Run`），不需要管理员权限；旧版本
放在「启动」文件夹里的 `Start Radar.vbs` 快捷方式会被顺手删掉，不会开机拉起两份。

**开机时要不要弹窗口**单独一个开关（「开机启动时」）：

| 选择 | 效果 |
|---|---|
| 只把图标放进托盘，不弹窗口（默认） | 登录时安静起服务，不抢焦点；想看界面双击图标 |
| 同时打开界面窗口 | 登录后直接把界面拉出来 |

- **关掉窗口 ≠ 停服务**：采集、公众号监听、任务队列都还在跑，托盘图标继续留着。
  双击托盘图标就把界面重新打开（按上面选的打开方式）。
- 托盘右键菜单：打开界面 / 打开方式（软件窗口·浏览器标签页）/ 重启服务 / 停止服务
  （保留托盘）/ 关窗口时（每次问·只关窗口·连服务退出）/ 开机自动启动 /
  开机启动时打开界面 / 打开数据文件夹 / **彻底退出（停止服务）**。
- **彻底退出**会写停止标记、等 api 与 worker 两个子进程收干净再走，不会留下占着
  8766 端口的孤儿进程。设置 → 高级与诊断 → 「桌面程序」里也能一键彻底退出。
- 浏览器标签页模式下没有「关窗口」这回事，关标签页只是关页面；要停服务用托盘菜单或
  设置里的「彻底退出」。
- 托盘菜单点右键没反应？先看 `data/logs/tray.log`——托盘跑在 `pythonw` 里没有控制台，
  出错只会写这个文件。`python radar_tray.pyw --selftest` 能验证菜单是否还能正常构造。

源码方式（没有 exe 时）两种都行，效果一样：

```bash
python radar.py start   # 只起后台，不开窗口
python radar.py stop    # 连托盘一起退
python radar.py where   # 各个目录在哪、数据库是哪一版
```

纯源码检出（没有 `Radar.exe`）可以双击 `Start Radar.vbs`，它转身去起同一个托盘外壳，
只是没有 exe 图标。**开机自启不会用 VBS**：一律写注册表的 `Radar.exe start`
（源码检出是 `pythonw radar_tray.pyw --autostart`）。

安装版的 `Radar.exe` 仍保留 `start / stop / restart / status / open / uninstall` 子命令，
供快捷方式和卸载程序调用；日常用托盘就够了。

第一次装完，打开页面会被带到 **设置 → 配置向导**，从上往下五步：
连接微信 → 接入大模型 → 汇报发到哪里 → 挑公众号 → 开机自启。
每一步都会当场告诉你"现在什么状态、还差什么、为什么是这样"，配完就是能用的状态。

## 把资料库调成你自己的样子

资料库不是只进不出的。四种手段，从轻到重：

**1. 删掉某一条。** 列表里每条右下角有「删除」，也可以勾左边的复选框批量删。
删的是"移出资料库"，正文和图片还留在磁盘上，勾上工具栏的「含已删除」就能找回来再点「恢复」。

**2. 屏蔽某个栏目。** 同一个公众号既发你要的综述，也发招聘、会议通知、会议报名、周报——
点右上角「过滤规则」，选公众号、填几个关键词（一行一个，或用逗号、竖线、顿号分开），
先「试跑」看会挡住哪些已收录的条目，确认再保存。规则**只匹配标题或「标题 + 简介」**，
不读正文：正文里出现一次"招聘"是常事（论文写"招聘博士后参与本项目"），拿正文屏蔽必然误伤。

**3. 隐藏低相关。** 精读打分低于阈值的条目落在"低相关"这一档，默认照常显示，
勾上工具栏的「隐藏低相关」才从列表里让位，随时能再打开。这一档的判断不太准，
所以没有把它做成默认隐藏——宁可多条，不可漏条。

**4. 引流软文不进库。** 一上来就让你"扫码下载资料"、正文又没有 DOI / 参考文献 / 图表编号的，
归档后直接移出资料库，理由写在「含已删除」里，误判可以一条条恢复。
判据看的是**位置**：真论文把二维码放文末，软文开头就让你扫码，所以只检查正文前 40%。
拿 658 条有正文的条目实跑，只拦下 3 条，人工核对全是软文。

## 看某个号最近发了什么

公众号库里点**公众号名字**，会打开一个像微信订阅号消息那样平铺的面板：封面图、标题、
时间一行好几个排开。里面有两个信息别处看不到：

- 这些推文**来自本机微信**，所以连**还没进雷达**的都在列，零接口费用；
- 每张卡片右下角直接告诉你它现在是什么状态：已收录 / 仅索引 / 已排除。

打开面板不需要这个号被启用、也不需要以前归档过——它就是拿来看「这个号值不值得收」的。
第一次点某个号会多花几秒（要扫一遍微信进程内存），所以面板是**两段式**的：先把上次
读到的列表显示出来，同时在后台重新读，读完了自己刷新，不用关掉重开。

面板下面那行小字是「为什么列表是这样」的说明书：

- `最后一条 2026-11-12（10 天前，本机微信里没有更新的记录）` —— **读到了，就是没更新**；
- `微信当前未运行，只能看本地归档` —— 打开微信再点一次就有；
- `本机关注列表里没有这个号` —— 可能已经取关，或者备注名和清单对不上；
- `正在读取本机微信… 已等 3 秒` —— 真的在读，不是卡住。

微信关着的时候攒下的推送，重开微信后最多 3 分钟就会自己补上（后台每 3 分钟做一次
增量解密，库文件没变时只花几十毫秒；详情页发现库有写入也会立刻排一次重读）。

面板上能做的三件事：

- **补录**：勾上再点「补录所选」，等于手动把这条塞进资料库，排队抓正文，不耗精读点数。
- **排除**：选个原因（广告、招聘、课程、生活娱乐，或自己写关键词）。选「以后同类也不再收录」
  会在「过滤规则」里自动加一条**该号专属**的规则——以后它再发同类标题，入库那一刻就被挡住，
  连索引都不留。规则随时能改能删，删了被挡住的条目会自动回来。
- **改分类**：面板右上角直接把 OPTIONAL 改成 CORE（或反过来），不用回列表勾选。

排除了不等于删了：卡片会变灰、打个「已排除」，点「恢复」就回来，原文一直在微信里。

## 微信 4.x 是怎么读的

升级到 4.x 之后读不到推文，通常是三件事里的一件，现在都处理掉了：

1. **通道被旧目录劫持**。3.x 的 `Documents\WeChat Files` 升级后还在（本机还是一条指向
   E 盘的软链接），只按"目录在不在"判断就会一直走 3.x，去读一份再也不更新的库。
   现在按"谁在更新"判定：`Weixin.exe` 在跑就是 4.x，两边都安静时比公众号库的最后写入时间。
2. **只读了第一个分片**。4.x 把消息切成 `biz_message_0.db`、`_1.db`……只读 `_0` 会漏掉
   历史（本机 `_0` 只有几十条，`_1` 里还有几百条）。现在按通配读全部分片。
3. **先读后刷新**。以前先读缓存再解密，关机期间进来的消息要等下一轮才看得到；现在
   每轮先 `refresh()` 再读。

**关机/关微信期间错过的推文**：下次启动会从上次读到的位置往后补，最多补
`catchup_days`（默认 30 天）；第一次接上 4.x 时补 `initial_backfill_days`（默认 7 天）。
前提是微信本地还留着那些消息——4.x 只保留它自己收到过的推送，**升级那一刻之前、
微信没开着的时候到达的推送，客户端本身就没有**，任何工具都补不回来。想让它尽量全，
开机后打开一次「订阅号消息」再让雷达跑一轮。

设置 → 高级与诊断里能看到实时数字：**近 7 天读到多少篇、其中多少篇来自你勾选的号**。
后者是 0 就说明最近发文的号不在名单里，不是读取坏了。

## 微信文件别堆在 C 盘

微信 4.x 的存储位置写在 `%APPDATA%\Tencent\xwechat\config\*.ini` 里，升级或重装
可能被重置回默认值，一重置就往 C 盘的「文档」下面灌。雷达会盯着它：

- 设置 → 高级与诊断 → **微信文件与 C 盘**，能看到 4.x 的真实存储根目录、3.x 的软链接
  指向、以及 C 盘上微信占了多少；
- 「补兜底链接」会在 `Documents\xwechat_files` 建一条指向外置盘的软链接。就算 ini 被
  重置，微信落下来的数据也还是写在外置盘，路径结构与 ini 生效时完全一致，不会出两份；
- 「回收安装包缓存」只删微信的 `update` 目录和 7 天前的日志，聊天记录一个字节都不碰。

## 数据安全：每日快照与直删

- 数据库每天自动快照到 `data/backups/radar-YYYYMMDD.db`，份数由设置里的
  `storage.backup_keep` 决定（默认保留 3 份，因为库大了每份都好几百 MB）；
  `radar-before-*` 这类手动留底**永远不参与滚动删除**。设置页有「立即备份」。
- 原文快照默认压成 `raw.html.gz`（gzip 无损，阅读页与配图不受影响），配图上限默认
  每篇 8 张；两项都在「设置 → 磁盘占用与备份」里改。旧条目要回收空间就跑一次
  `python scripts/compress_raw.py --apply`。
- 程序自己产生的临时文件、缓存、旧安装包走 `app/services/purge.py` 直删，**不进回收站**；
  命令行侧对应 `python radar.py tidy`（清 `.tmp` + 直删回收站里本项目的记录）。
- 用户资料（`data/documents`、`data/blobs`）不在直删范围里，删之前先备份。

## 改坏了怎么办

代码有版本控制，不用怕改崩。

```bash
python radar.py status                  # 现在有哪些改动还没存
python radar.py save "改了什么"          # 存一个版本
python radar.py list                    # 看历史，带编号
python radar.py undo                    # 退回上一个版本
python radar.py back 3                  # 退回列表里第 3 个版本
python radar.py config-restore          # 只把设置恢复成上次保存的样子
```

**每一次回滚都会先把当前状态留底**，所以退错了还能再退回来。`undo` 的语义按情况定：
有未保存改动时是"丢掉改动回到上次保存"，工作区干净时是"退回再上一个已保存版本"。

## 换台电脑 / 给别人用

### 用安装包（推荐）

双击 **`RadarSetup.exe`**：可以选安装目录、要不要桌面快捷方式、要不要开机自启；
它自己找 Python、建虚拟环境、装依赖、写配置、建数据库，最后可选直接打开页面。
装完可以在 设置 → 配置向导 里把微信和大模型配好，不需要碰命令行。

静默安装（批量装机、自动化测试用）：

```bash
RadarSetup.exe /S --dir=D:\Radar --port=8899 --no-autostart --no-desktop --no-launch
```

卸载走 Windows「应用和功能」，或者 `Radar.exe uninstall`（会问两次：要不要卸、要不要连
`data\` 里的资料一起删）。

### 从源码装（开发、或想看得见每一步）

把整个文件夹拷过去，跑：

```bash
python install.py
```

安装向导会建虚拟环境、装依赖、问几个配置问题（端口、用哪个模型、要不要推送）、
把数据库建起来。已经装过再运行是安全的，不会覆盖现有设置。

`python install.py --reconfigure` 重新配一遍，
`--reinstall` 重装依赖，
`--dry-run` 只检查不安装（想确认这个包完整时用）。
`Install.vbs` 是同一件事的双击版，留着给不方便开命令行的时候用。

### 自己打安装包

```bash
python tools/build_exe.py            # payload.zip + Radar.exe + RadarSetup.exe
python tools/build_exe.py --launcher # 只重打 Radar.exe
```

产物在 `dist/exe/`。`Radar.exe` 只做"拉起 supervisor、开浏览器、停服务"，
依赖住在安装目录的 `.venv` 里，所以改代码不用重打 exe；`RadarSetup.exe` 才是要发给别人的那个。

### 发一个新版本（各机器自动更新）

一句话：

```bash
python radar.py release "这一版改了什么"
```

它按顺序做：跑测试 → 版本号 +1（`--bump minor` / `--version 1.2.0` 可以改法）→
提交并打 tag → 打安装包 → 建 GitHub Release 传上去 → 回写 `version.json`。

仓库是 <https://github.com/forscienceshw/hermes-radar>，公开库，装过的机器不需要任何凭据
就能读版本号、下载安装包。

客户端那边：每次启动 20 秒后后台查一次（同一天只查一次），发现新版本就在顶栏显示
「新版本 x.y.z 可更新」。点它跳到 设置 → 参数设置 → 版本与更新，可以手动检查、
下载（带 sha256 校验）、然后一键重启并安装。

装的过程是原地顶替：
- 只替换程序文件，`data/`、`config/settings.json`、`config/secrets*.json`、`.venv` 全保留；
- 上一版装过、这一版不再有的文件，按安装清单精确删掉，不留残渣；
- `requirements.txt` 没变就跳过那 80 MB 的依赖安装，几秒装完；
- 装完自动把新版本拉起来，桌面和开始菜单的快捷方式指向同一处，不会多出一份。

网络查不到更新时软件照常跑，只是不提示；也可以在项目页手动下安装包双击覆盖。
坏了想退回去：装回旧版本的安装包即可，`data/` 不会被碰。

更新检查的三个源（谁也拦不住的时候才认输）：GitHub API 的 latest release、
jsDelivr CDN、raw.githubusercontent.com。国内直连 GitHub 不稳的话，在
`config/settings.json` 里把 `update_mirror` 填成 `https://ghproxy.net/` 之类的前缀。

### 只搬程序，不搬资料

```bash
python radar.py pack
```

生成 `dist/hermes-radar-<版本>-<日期>.zip`，里面只有代码、模板和安装脚本，
几百 KB。解压出来跑一次 `install.py` 就是一套干净的实例。

### 连资料一起搬

除了上面那个包，再拷 `data/` 整个目录（这个仓库不跟踪它）。
`data/` 里有：

| 目录 | 内容 | 能不能不拷 |
|---|---|---|
| `data/radar.db` | 条目、评分、笔记、对话 | 不拷就是空的资料库 |
| `data/documents/` | 每篇文章的离线页面与正文 | 不拷则阅读页打不开原文 |
| `data/blobs/` | 图片原图（按内容寻址） | 不拷则图看不全 |
| `data/papers/` | 下载的论文 PDF | 不拷则要重新下 |
| `data/logs/`、`data/backups/` | 日志和历史备份 | 可以不拷 |

拷完在目标机器上跑一次 `install.py`，它不会覆盖已有数据库，只补环境。

**密钥不会跟着走。** `config/secrets.dpapi.json` 用 Windows DPAPI 加密，只对
"这台机器 + 这个 Windows 账户"有效。到了新机器，旧的解不开，程序会当成没配，
在设置页重新填一次即可（`secret_status()["broken"]` 会列出哪些需要重填）。
这也意味着：**别把 secrets 文件发给别人**，发了也没用，但没必要。

## 目录结构

```
app/          后端：采集、归档、分析、推送、API
web/          前端：单页界面，无构建步骤
installer/    安装程序（RadarSetup.exe）与主程序入口（Radar.exe）的源码
tools/        工程脚本：版本控制、打包、打 exe（与业务无关，可单独拷走）
scripts/      一次性数据修复脚本
tests/        单元测试
config/       settings.json（入库）、secrets（不入库）、settings.example.json
data/         运行时数据，不入库
VERSION       版本号
radar.py      所有日常操作的入口（版本控制 / 启停 / 打包）
install.py    源码模式安装向导
Install.vbs   双击安装（源码模式）
```

## 依赖

Python 3.11+，Windows（微信公众号监测与 DPAPI 密钥存储依赖 Windows API）。
依赖清单在 `requirements.txt`，安装向导会处理。

## 已知的取舍

- 微信公众号自动监测读的是本机微信的数据库：3.x 在 `Msg/PublicMsg.db`，4.x 在
  `xwechat_files\<账号>\db_storage\message\biz_message_*.db`。两边都只读、不联网。
  4.x 已经在 4.2.0 上真机验证过（见「微信 4.x 是怎么读的」）。
- 微信和本程序之间没有"扫码授权读数据库"这种接口可用——扫码只能登录，授权不了磁盘文件。
  所以走的是"在本机只读地取一次密钥"这条路，全程不联网、不改微信的文件。
- 图片分诊走视觉模型，按张计费，有每日调用上限（`llm.daily_call_limit`）当保险丝。
- 离线页面是抓取当时的样子，原文被删也能看；但发布方后来改过的地方不会同步。
- 公众号的**图片消息**（分享链接里带 `t=pages/image_detail` 的那种，也叫"小绿书"）
  拿不到正文：换微信 iOS、安卓、桌面浏览器三种 UA 实测，微信一律只返回人机验证页。
  这类条目会退化成"分享卡片"——用转发时那段文字说明和封面拼一个本地阅读页，
  详情里标「卡片摘要」，正文缺失的部分补不回来。
