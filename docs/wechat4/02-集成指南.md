## 步骤 0 · 先判断你手上的项目是哪一种

| 你的项目现状 | 要做的事 |
|---|---|
| 只有 3.x 读取（`wechat_self_archive.py` 里走 `WeChat Files\Msg\*.db`） | 走完整流程；4.x 作为**新增分流**，不要动 3.x 分支 |
| 已有 4.x 适配但"扫内存找 `x'<hex>'`" | 那个方法在 4.1+ 已经失效，直接用本包的 `wechat4_live.py` 替换其取密钥逻辑 |
| 全新接入 | 同样走完整流程 |

**重要**：不要删掉 3.x 分支。3.x 和 4.x 的数据目录不同、加密参数不同，必须分流。

## 步骤 3 · 分流：3.x 还是 4.x

在 `app/services/wechat_self_archive.py` 里加三个小工具（原文见本包 `src/`）：

```python
def _wechat3_present() -> bool:
    root = Path.home() / "Documents" / "WeChat Files"
    try:
        return root.is_dir() and any(root.iterdir())
    except OSError:
        return False


def _wechat4():
    """本机有 4.x 且（在跑 或 有解密缓存）时返回模块，否则 None。"""
    try:
        from . import wechat4_live
    except Exception:
        return None
    try:
        return wechat4_live if wechat4_live.available() else None
    except Exception:
        return None


def _wechat4_sync(module) -> dict:
    try:
        state = module.refresh()
    except Exception as exc:
        return {"error": str(exc)[:300], "refreshed": 0, "skipped": 0, "failed": []}
    return {"refreshed": state.refreshed, "skipped": state.skipped,
            "failed": state.failed[:5], "key_source": state.key_source,
            "storage": str(state.storage)}
```

然后在两个 poll 入口的最前面分流（**保持原 3.x 代码不动**）：

```python
async def poll_wechat_self(source, scope):
    config = json_loads(source.get("config_json"), {}) or {}
    if not _wechat3_present():
        module = _wechat4()
        if module is not None:
            previous = json_loads(source.get("cursor_json"), {}) or {}
            candidates, cursor = _wechat4_self_candidates(module, source, config, previous)
            cursor["sync"] = _wechat4_sync(module)
            return _apply_history_policy(candidates, cursor, config, source["id"])
    # ↓ 原 3.x 逻辑，原样保留
    candidates, cursor = sync_self_chat(...)
    return _apply_history_policy(candidates, cursor, config, source["id"])


async def poll_wechat_public_local(source, scope):
    config = json_loads(source.get("config_json"), {}) or {}
    previous = json_loads(source.get("cursor_json"), {}) or {}
    if not _wechat3_present():
        module = _wechat4()
        if module is not None:
            candidates, cursor = _wechat4_public_candidates(module, source, config, previous)
            cursor["sync"] = _wechat4_sync(module)
            return candidates, cursor
    # ↓ 原 3.x 逻辑，原样保留
    ...
```

> `_apply_history_policy(candidates, cursor, config, source_id)` 是从原 3.x 里**抽出来**的公共函数
> （原本内联在 `poll_wechat_self` 里）：负责按 `auto_process_after` / `history_mode` 决定
> "历史只建索引"还是"正常处理"，并统一补 `candidate["source_id"]`。抽出来是为了两条通道共用。

## 步骤 4 · 候选构造（字段契约必须对齐）

你的采集管线大概率要求 candidate 是某个固定形状。对照下面这份（本项目的形状）：

```python
{
  "source_id":   source["id"],
  "kind":        "article",
  "url":         item["url"],                    # ★ 原始完整链接，绝不要裁参数
  "canonical_url": canonical_url(item["url"]),   # 去重用
  "external_key": f"public4:{talker}:{item['local_id']}",   # 幂等键
  "title":       item["title"] or item["url"],
  "author":      names.get(talker, item["account"]),
  "published_at": epoch_iso(item["create_time"]),           # ISO8601，UTC
  "metadata": { "share_channel": "wechat_public_local",
                "wechat_version": "4.x",
                "wechat_account_id": talker,      # gh_xxx
                "public_message_id": item["local_id"],
                "description": item["digest"],
                "catalog_matched": talker in catalog_matched },
}
```

两个数据源函数（在 `wechat4_live` 里）：

## 步骤 5 · 增量游标（避免"勾选后要等新文章"）

4.x 的游标只用一个字段就够：`last_create_time`（秒）。

但有个体验问题：用户新勾一个公众号，如果只看 `last_create_time`，他要从"勾选这一刻"开始等。
所以再加一个**启用名单指纹**，一变就回填：

```python
effective = sorted(a for a in allowed if a not in excluded) if enforce_allowlist else []
fingerprint = hashlib.sha1("|".join(effective).encode()).hexdigest()[:16]
days  = max(1, min(365, int(config.get("initial_backfill_days", 7) or 7)))
since = int(previous.get("last_create_time") or 0)
if previous.get("catalog_fingerprint") != fingerprint or not since:
    since = int(time.time() - days * 86400)      # 名单变了 → 回填最近 N 天
...
cursor = {"initialized": True, "wechat_version": "4.x",
          "last_create_time": max(newest, int(previous.get("last_create_time") or 0)),
          "catalog_fingerprint": fingerprint,
          "tracked_accounts": len(effective), ...}
```

> 注意 `last_create_time` 取 `max(newest, previous)`：回填窗口不会让游标倒退。

## 步骤 6 · 公众号目录与启用名单

```python
directory = wechat4_live.oa_directory()   # {gh_xxx: {'name': ..., 'aliases': {...}}}
rows      = wechat4_live.account_rows()   # 列表版，带 name/account_id/alias/description
```

`account_rows()` 的命名优先级是 **备注 > 品牌昵称 > 昵称 > 微信号 > gh_ 原始 id**，
`aliases` 里带全部候选名，用于"用户按名字勾选"时的模糊匹配。

建议的默认行为（本项目已验证）：**新装环境同步出全部公众号，但 `enabled` 一律 0**，
让用户自己勾。用 `use_catalog=True` + 空名单时过滤结果为空 → 一条都不采，这是正确的。

对应 API（本项目的实现，你可以照搬）：

```
POST /api/wechat/accounts/sync-local    # 从本机微信同步全部公众号，enabled=0
GET  /api/wechat/accounts               # 列表 + stats（注意 SUM() 要 COALESCE）
POST /api/wechat/accounts/bulk          # 批量启用/停用
```

`SUM()` 在空表上返回 `NULL`，前端做减法会变 `NaN`，所以要：

```sql
COALESCE(SUM(enabled),0) enabled, COALESCE(SUM(CASE WHEN fit='CORE' THEN 1 ELSE 0 END),0) core
```

## 步骤 7 · 归档链路：把"验证页"当成"稍后再试"，不是永久失败

`app/services/archive.py` 里定义专用异常：

```python
class WechatNeedsVerification(RuntimeError):
    """微信把直接抓取挡在了人机验证页后面。

    这不是"这篇文章坏了"，多半是本机把链接参数裁了、或者真的被风控了。
    必须被当成"稍后重试"，而不是把任务记成永久失败。
    """
    retry_after_minutes = 45
```

抓取处（原来是 `raise ValueError("微信返回验证页或非正文页面")`）：

```python
if wechat and content_root is None:          # content_root = soup.select_one("#js_content")
    gone = detect_gone(None, _page_text(response))
    if gone:
        raise SourceGone(gone)
    raise WechatNeedsVerification(
        "微信返回了人机验证页（本机直连被风控限流）。文章没有丢：链接和标题已经收下，"
        f"{WechatNeedsVerification.retry_after_minutes} 分钟后会自动重试抓取。")
```

`app/worker.py` 里加一个**分级重试**（不消耗普通重试次数，但要能收敛）：

```python
except WechatNeedsVerification as exc:
    previous = str(job.get("last_error") or "")
    seen = 0
    if previous.startswith("微信验证 #"):
        try:
            seen = int(previous[len("微信验证 #"):].split("：", 1)[0].strip())
        except ValueError:
            seen = 0
    seen += 1
    if seen > 3:                                  # 3 轮还不行就如实收尾，别无限循环
        self.db.retry_job(job, f"{type(exc).__name__}: {exc}", force_dead=True)
        if item_id:
            self.db.clear_runtime(f"progress:{item_id}")
            self.db.fail_item(item_id, "微信连续 3 轮人机验证拦截，正文和离线页都没拿到；"
                                       "链接和标题已保留，风控放开后可重新尝试归档。",
                              status="insufficient")
    else:
        minutes = (30, 90, 180)[min(seen - 1, 2)]
        run_at = (datetime.now(timezone.utc) + timedelta(minutes=minutes)).isoformat(timespec="milliseconds")
        self.db.reschedule_job(job["id"], run_at, reason=f"微信验证 #{seen}：{exc}", reset_attempts=True)
```

> 为什么要 `reset_attempts=True` + 自己数 `seen`：普通重试次数（`max_attempts`）是给网络抖动用的，
> 验证页可能几小时后才放开，不能把预算烧在这上面；但也不能无限等，所以自己记"第几轮"。

## 步骤 8 · 前端（3 处，与业务逻辑无关但直接影响可用性）

1. **公众号名字要能点开**（如果你需要"点名字看该号全部文章"）：
   本项目**没有**这个功能，`renderWechat` 里名字是纯文本 `<b>${esc(x.name)}</b>`。
   要加的话：行上加 `data-wa-home="${x.account_id}"`，点击后调
   `GET /api/items?account=<gh_xxx>`（需要先给 `/api/items` 加 `account` 过滤参数，
   按 `metadata_json -> '$.wechat_account_id'` 或 `items.author` 过滤）。

2. **"等微信放行"要和"归档中"分开显示**：
   `/api/items` 的 `active_job` 目前只有 `archive`/`analyze`。
   本项目加了一个 `verify`：当 job 的 `last_error` 含"人机验证/微信验证"时返回 `verify`，
   前端渲染成「等微信放行」而不是「归档中」，否则用户会以为卡死。

3. **全局函数不要重名**：`app.js` 和 `setup.js` 都曾有顶层 `function renderWechat(...)`，
   后者覆盖前者，导致"公众号库点一下就报 Cannot read properties of undefined"。
   修法：改名 + 把 `setup.js` 整体包进 `(function(){ 'use strict'; ... }())`。

## 数据结构参考（`wechat4_live` 的公开面）

```python
class SyncState:            # refresh() 的返回值
    storage: Path           # db_storage 目录
    cache: Path             # 明文缓存目录（DATA_DIR/wechat4）
    keys: dict[str, str]    # salt_hex -> key_hex
    key_source: str         # "memory(23 候选)" / "缓存" / ""
    refreshed: int          # 本次重新解密的库数
    skipped: int            # 指纹没变而跳过的库数
    failed: list[str]       # 失败原因（ humanos 可读）

quick_status() -> {'running','pids','storages','databases'}
available()    -> bool      # 进程在跑 或 有 keys.json + 缓存
refresh(storage=None, cache=None, budget=90.0, force=False) -> SyncState
account_rows(cache=None, limit=20000) -> list[dict]
oa_directory(cache=None) -> {gh_x: {'name','aliases'}}
official_articles(since_ts=None, per_account=300, cache=None) -> list[dict]
self_links(since_ts=None, per_chat=300, cache=None) -> list[dict]
article_of(xml_text) -> {'url','canonical','title','digest','account_nick'} | None
```
