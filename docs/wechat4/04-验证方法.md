# 04 · 在新机器上怎么验证

分 5 层，**从下往上**。任何一层不过，就不要往上一层接——否则你会在上层看到一堆莫名其妙的失败。

---

## 第 0 层：环境前提（30 秒）

```bash
# 微信 4.x 是否在运行
tasklist /FI "IMAGENAME eq Weixin.exe"

# 依赖是否齐
python -c "import Crypto, zstandard, psutil; print('deps ok')"
```

期望：能看到 `Weixin.exe`；`deps ok`。

注意：

- 微信 **3.x 的进程叫 `WeChat.exe`，4.x 叫 `Weixin.exe`**，别搞混。
- 不需要管理员权限（实测同用户即可读内存）。
- 微信 4.x 安装目录可能在非默认位置，但**数据目录**由 `%APPDATA%\Tencent\xwechat\config\*.ini` 决定，
  不要靠猜。

---

## 第 1 层：能不能定位数据（10 秒）

```bash
python tools/probe.py status
```

期望：

```
Weixin.exe 在跑： True | PID： [....]
db_storage 目录 ： ['...\xwechat_files\<wxid>_<4位>\db_storage']
数据库数量      ： 20
```

不过的话按提示查：

| 现象 | 原因 |
|---|---|
| `db_storage 目录：没找到` | 没登录过 / 存储路径被改到别处 / 装的是 3.x |
| 目录对但库数量 0 | 微信刚装还没数据，先去微信里打开一次「订阅号消息」 |
| `Weixin.exe 在跑： False` | 微信关着。已解密的缓存还能读，但拿不到新消息 |

## 第 2 层：能不能取密钥 + 解密（首次约 20 秒）

```bash
python tools/probe.py refresh
```

期望：

```
密钥来源：memory(2x 候选)
更新 20 个库，跳过 0 个，失败 0（4.x 秒）
```

再跑一次，期望变成 `密钥来源：缓存｜更新 0 个，跳过 20 个`（说明增量缓存生效）。

**必须检查的一项**：解密出来的库能不能通过 SQLite 完整性检查。

```bash
python - <<'PY'
import sqlite3, pathlib
root = pathlib.Path("data/wechat4")          # Windows 上换成实际 DATA_DIR
bad = []
for p in sorted(root.rglob("*.db")):
    con = sqlite3.connect(f"file:{p.as_posix()}?mode=ro", uri=True)
    try:
        r = con.execute("PRAGMA integrity_check").fetchone()[0]
    finally:
        con.close()
    if r != "ok":
        bad.append((p.name, r[:60]))
print("bad:", bad or "none")
PY
```

期望 `bad: none`（`*_fts.db` 可能报 `SQL logic error`，那是 FTS5 影子表的老问题，不影响正文）。

**如果这里出现 `invalid page`** → 你的 WAL 合并漏了 salt 校验，见 `03-踩坑清单.md` 坑 3。

## 第 3 层：能不能拿到文章标题和链接（2 秒）

```bash
python tools/probe.py articles 7     # 公众号推送
python tools/probe.py links 7        # 自己转发的
python tools/probe.py accounts 20    # 关注的全部公众号
```

期望看到真实中文标题和带 `chksm` 的完整链接。

不过的话：

| 现象 | 原因 |
|---|---|
| `articles` 0 条 | 这个微信没关注公众号 / 近 N 天没推送 / 没打开过「订阅号消息」 |
| `links` 0 条 | 没给自己或文件传输助手发过公众号链接 |
| 标题是 `gh_xxxxxxxx` | 名字优先级没做对，见坑 11 |
| 正文列是空的 | 没装 `zstandard`，或压缩标记判断错，见坑 4 |

## 第 4 层 ★最关键：能不能真正抓到正文

```bash
python tools/repro_url_param.py
```

期望：

```
① 完整原始链接        HTTP 200 len= 3588155  正文 ✅
② 裁到 biz/mid/idx/sn HTTP 200 len=   17693  滑块验证码 ❌

结论：完整链接能拿到正文。集成时务必保留原始 query 参数（坑 1）。
```

三种结论与对策：

| ① 的结果 | 含义 | 对策 |
|---|---|---|
| 正文 ✅（几 MB） | 正常 | 按 `02-集成指南.md` 接下去；**务必保留原始参数** |
| 滑块验证码 ❌ | 连完整链接都被挡：真的是 IP 风控 | 换出口（手机热点 / 换宽带 / 配代理，见下） |
| `参数错误` ❌ | URL 里的 `&amp;` 没还原 | 见坑 2 |

如果是真的 IP 风控，验证"放开没有"的方法：再跑一次这个脚本；或者在程序里点
`POST /api/diagnostics/wechat-direct`。`综合 state=ok` 就说明放开了。

> 实践经验：**绝大多数"抓不到正文"都不是风控，是坑 1。** 先排除参数问题，再怀疑网络。

## 第 5 层：端到端（归档 + 精读）

1. 触发一次采集（`POST /api/sources/{id}/run` 或等调度）
2. 等条目从 `discovered` → `archived` → `ready`
3. 检查磁盘：

```bash
ls data/documents/<item_id>/          # 期望看到 reader.html 和 content.txt
python -c "print(open('data/documents/<item_id>/content.txt',encoding='utf-8').read()[:200])"
```

期望 `content.txt` 有几千到几万字符的真实正文，`reader.html` 能用浏览器打开、图片在。

4. 条目状态含义（本项目）：

| 状态 | 含义 |
|---|---|
| `discovered` | 只拿到链接和标题 |
| `archived` | 正文+图片已存本地，等精读 |
| `ready` | 已精读（有摘要/评分/标签） |
| `filtered` | 本地初筛判低相关，保留不精读 |
| `insufficient` | 拿不到足够正文，没做猜测性精读 |
| `error` | 失败 |

`insufficient` 要能区分原因：**图片分享页**（`t=pages/`，永远拿不到）和
**微信验证页**（会重试，之后可能成功）必须是两条不同的路径，见坑 14。

```bash
python tools/probe.py status && \
python tools/probe.py refresh && \
python tools/probe.py articles 7 | head -20 && \
python tools/probe.py links 7 | head -20 && \

```

按顺序看输出，第一个失败的地方就是要修的地方。

## 附：如果你要证明"不是我的代码的问题"

用同一套归档器抓一个**非微信**的网页（arXiv / Nature 都行），如果也能出正文和离线页，
就说明抓取/解析/离线页这条链是好的，问题被限定在"微信那一家"：

```python
import asyncio
from app.services import archive
r = await archive.archive_web({'id': 'probe-1', 'url': 'https://arxiv.org/abs/2501.00001',
                               'metadata': {}})
print(r['title'], len(r['text']), r['html_path'])
```

本项目最后一次这样测的结果：

```
arxiv.org/abs/2501.00001  → title 正常，正文 4772 字符，reader.html 已生成
nature.com/articles/...   → title 正常，正文 4134 字符，reader.html 已生成
```

这条自检能把你从"是不是全网都抓不到"的错误结论里救出来。
