# 微信 4.2 试装与只读验证

这份文档回答一个问题：**怎样在不弄丢现在这套 3.9.9.43 的前提下，试一下 4.2 的数据库能不能读。**

先说结论：

- **能共存。** 3.9 和 4.x 的安装包名不同、安装目录不同、数据目录也不同，可以同时装在一台机器上。
- **旧数据不会被动。** 4.x 第一次登录时会**新建** `xwechat_files`，不会删除 `WeChat Files`。
- **4.x 的密钥必须从运行中的进程里取**，离线文件里没有。所以"不装 4.2 就把它破了"这件事不成立，只能装上去读。

---

## 一、动手之前：三条红线

1. **两个版本的数据目录必须在同一个磁盘分区。**
   腾讯的说明写明：4.0.6.33 及以上，如果 4.x 的存储路径和 3.9 不在同一分区，或者文件系统不支持硬链接（比如 exFAT），
   4.x 会把 3.9 的**附件从旧目录挪到新目录**。挪动不是复制——那就真的动了你的老数据。
   你现在 `WeChat Files` 在 `C:`，所以 4.2 的数据目录**不要改到 D:/E:**，让它留在 `C:` 默认位置。

2. **不要点"清理历史版本冗余聊天数据"。**
   那是 4.x 里用来删 3.9 数据的入口。装好之后先别碰，等验证完、用一段时间再说。

3. **不要手动把 `WeChat Files` 里的文件拷进 `xwechat_files`。**
   腾讯明确说新旧数据不可混用；拷进去不仅读不出来，还可能让 4.x 认错库。

## 二、备份什么（只备不可再生的部分）

图片、视频、文件这些附件都在服务器上，能重新下载；**只有 `Msg` 目录里的加密数据库是不可再生的**。

现在这套：

```
C:\Users\for_s\Documents\WeChat Files\wxid_fxdieacgcmn722\Msg     约 5.0 GB
```

把它复制到 E 盘（有 455 GB 空闲，放得下）：

```bat
robocopy "C:\Users\for_s\Documents\WeChat Files\wxid_fxdieacgcmn722\Msg" ^
         "E:\WeChatBackup\Msg-20261116" /E /COPYALL /R:1 /W:1
```

`/COPYALL` 会连时间戳和 ACL 一起复制，将来能原样放回。

顺手记下两件事，回退时要对得上：

| 项目 | 当前值 |
| --- | --- |
| 微信版本 | 3.9.9.43 |
| 程序路径 | `D:\program\WeChat\WeChat.exe` |
| 数据根 | `C:\Users\for_s\Documents\WeChat Files` |
| 账号 | `wxid_fxdieacgcmn722` |

## 三、装 4.2

1. 从微信官网下载 4.2.0 的 Windows 安装包（不要用第三方站的"绿色版"）。
2. 安装时把目录定在**默认位置**（`C:\Program Files\Tencent\Weixin`），不要覆盖 `D:\program\WeChat`。
3. 装完扫码登录，如果它问要不要迁移历史消息，选**不迁移**（我们只是要验证能不能解密，不需要历史）。
   它照样会在 `C:\Users\for_s\Documents\xwechat_files\` 下建自己的库。
4. 打开一次公众号消息列表，让 `message_*.db` 里有真实数据。

## 四、验证

4.2 保持登录、别退出，然后在项目目录运行：

```bat
python scripts\wechat4_probe.py
```

它会依次做四件事，每一步都会打印结果：

1. 找到 `Weixin.exe` 进程和 `xwechat_files\<账号>\db_storage`；
2. 只读扫描该进程内存，找 `com.Tencent.WCDB.Config.Cipher` 里 `x'<64 位十六进制>'` 形式的候选密钥；
3. 对每个库用 SQLCipher 4 参数（AES-256-CBC / HMAC-SHA512 / PBKDF2 256000 轮 / 页 4096 / 预留 80 字节）逐个试开；
4. 报告哪些库能读、哪些打不开（空库打不开是正常的）。

也可以直接在网页里做：**设置 → 配置向导 → 第 1 步「尝试读取 4.x」**。

想顺便看看能不能抓到公众号链接：

```bat
python scripts\wechat4_probe.py --links 50
```

## 五、结果怎么解读

| 输出 | 含义 | 下一步 |
| --- | --- | --- |
| `找到 N 个候选密钥` + `可读库 M 个` | 破解成功，密钥和库都对上了 | 把输出发我，我把 `message_*.db` 的字段映射接进归档链路 |
| `内存里没找到 x'…' 形式的密钥` | 4.2 换了密钥的存放方式 | 需要换扫描策略（按 WCDB 结构定位而不是按字符串），把输出发我 |
| `OpenProcess 失败，错误 5` | 权限不够 | 用管理员身份运行终端再试 |
| `没找到 xwechat_files` | 还没登录或改过存储路径 | 微信里「设置 → 文件管理」确认路径 |

`code` 里已经有一份 4.x 适配器（`app/services/wechat4.py`），但**没有在真机上验证过**，
所以网页上只显示"4.x 可尝试"，不会假装它能用。跑通一次之后我再把状态改成"已支持"。

## 六、回退

任何一步不满意，都能回到现在：

1. **只卸载 4.x**：设置 → 应用 → 微信（4.x）→ 卸载。卸载时会问要不要删聊天记录，选**不删**。
2. `D:\program\WeChat\WeChat.exe` 没被碰过，双击就是 3.9.9.43；它的数据还在 `C:\Users\for_s\Documents\WeChat Files`。
3. 万一 3.9 提示"版本过低"，那是因为它的文件管理指向了 4.x 的目录：在 3.9 里「设置 → 文件管理」改回
   `C:\Users\for_s\Documents\WeChat Files` 即可。
4. 真出事（数据目录被弄乱）就把第二节备份的 `Msg` 整个放回去。

> 3.9 和 4.x 的数据**不互通**：在 4.x 里收到的新消息，3.9 看不到。腾讯也不建议长期交替使用。
> 所以这套流程的定位是"验证一次，然后决定要不要整体迁到 4.x"，不是"两个版本长期并用"。

## 七、验证通过之后

雷达这边要做的（我来接）：

1. `wechat4.py` 里把 `message_*.db` 的表名/字段名映射补全（4.x 按会话分表，正文常常是 zstd 压缩）；
2. `wechat_self_archive.py` 增加按版本分派：3.x 走现有路径，4.x 走新适配器；
3. 设置页把 4.x 的状态从"可尝试"改成"已支持"，并把「需要重新授权」接进去；
4. `requirements.txt` 增加 `zstandard`（只在 4.x 路径上才导入，3.x 不受影响）。
